# v0.97 — Chatterbox-Turbo Controls and Performance Tags

v0.97 extends the RTX 2060-compatible Chatterbox-Turbo workflow without treating local hardware limits as permanent product limits.

## Hardware and engine policy

- Chatterbox-Turbo remains the local/default Chatterbox engine for the current RTX 2060 development machine.
- Controls must reflect capabilities the active engine actually supports; unsupported controls must not silently appear to work.
- Future versions may add original Chatterbox and remote GPU execution as separate capabilities rather than replacing Turbo.
- The UI and saved metadata should be capability-driven so stronger local or remote engines can expose additional controls later.

## Turbo generation controls

Primary controls:

- Temperature
- Repetition penalty
- Top-p

Advanced controls in a collapsed section:

- Top-k
- Optional seed; blank means preserve current random behavior
- Optional increment-seed-for-queued-takes behavior
- Reference loudness normalization when supported by the installed Turbo runtime

Every generated job and take should preserve requested and effective engine options, including the effective seed used for each queued take.

## Tagged Script performance syntax

The source script remains human-readable and is preserved verbatim.

### Multi-line style block

```text
[sarcastic]
BROTHER: Go fax somebody, Pops.
ENDER: Spew plastic spaghetti, kiddo.
[/sarcastic]
```

The parser applies `sarcastic` to each speaker line in the block. Each independently generated line receives the real Turbo token in its synthesis text.

### Single-line style

```text
BROTHER: [angry] Do not touch my paper tray.
```

A leading inline style applies only to that speaker line. Inside a block, an inline style overrides the block for that line and the block style resumes afterward.

### Positional vocal events

```text
ENDER: I am a precision machine. [chuckle] Most of the time.
```

Vocal-event tags remain at their exact position in the synthesis text because placement matters.

## Parser rules

- Preserve the original script text exactly when saving scripts/projects.
- Convert block and leading inline performance styles into per-line metadata.
- Preserve positional vocal-event tags in spoken/synthesis text.
- Do not permit nested performance-style blocks in v0.97.
- Preflight must report unsupported tags, unclosed blocks, mismatched closing tags, closing tags without open blocks, nested blocks, and empty performance blocks.
- Inline style overrides the active block style for only that line.

## UI behavior

- Synthesize shows Turbo controls only while Chatterbox-Turbo is selected.
- Include an Insert performance tag control that inserts at the cursor.
- Tagged Script parsed preview and Take Manager show performance style as a badge/metadata field rather than mixing it into the editable spoken-text field.
- Take Manager controls remain lazy-rendered and support inherit, override, no style, and reset-to-script behavior.
- Advanced sampling controls remain collapsed by default to limit clutter.

## Saved metadata and diagnostics

Persist and log:

- requested engine options
- validated/effective engine options
- performance style
- synthesis text sent to the engine
- source spoken text
- effective seed
- unsupported or ignored options
- engine/runtime capability report

Diagnostics should log compact text previews and lengths rather than full scripts.

## Accepted authoring guidance for AI-generated scripts

AI script adaptation should:

- use standalone opening/closing style blocks for styles spanning multiple consecutive speaker lines;
- use a leading inline style tag for a single-line performance;
- place vocal-event tags at the exact event location;
- close every block;
- avoid nested performance blocks.
